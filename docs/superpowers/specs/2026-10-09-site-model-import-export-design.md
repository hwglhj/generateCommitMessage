# 站点多模型快速切换与配置导入导出设计

## 背景

AI Commit 的 API 模式支持多个站点配置，但每个站点当前只保存一个模型。提交面板的快速模型菜单也按配置展示，无法在同一站点的多个模型之间直接切换。站点数量增加后，用户需要频繁打开设置页修改站点或模型。

同时，站点配置目前只能在设置页手工维护，缺少跨机器备份和迁移能力。Windows 用户需要使用原生文件选择器，并避免导入导出操作破坏现有 PasswordSafe 密钥。

## 目标

1. 在提交面板闪电按钮旁的快速模型菜单中，按站点分组展示该站点的多个模型。
2. 点击模型时同时激活站点和该站点的当前模型，后续生成立即使用新选择。
3. 在 Generate Commit Message 设置页增加站点信息导入和导出操作。
4. 导出默认不包含 API Key，可由用户勾选后显式导出。
5. 导入同一站点 ID 时覆盖已有站点；无 API Key 的导入保留本机密钥。
6. 对非法文件进行完整校验，校验失败时不写入任何配置。
7. 保持旧配置兼容，并兼容 Windows 路径、中文文件名和 IntelliJ 平台 UI 生命周期。

## 非目标

- 不为 CLI 模式增加站点配置或远程模型发现。
- 快速切换菜单打开时允许在后台调用各站点现有 `/models` 接口刷新候选；请求失败时保留该站点已保存的模型列表。
- 不改变现有 API 请求协议、PasswordSafe 存储机制或提交信息生成流程。
- 不自动提交、推送或合并 Git 变更。

## 数据模型

### 站点配置

`ApiProviderConfig` 增加模型列表字段：

- `model`：站点当前选中的模型，继续作为兼容字段和请求入口。
- `models`：站点可用模型列表，保存去重、去空后的模型名称。

已有配置加载时执行兼容迁移：

1. 如果 `models` 为空且 `model` 非空，把 `model` 放入 `models`。
2. 如果 `model` 不在 `models` 中，把它加入 `models`。
3. 保持原站点 ID、名称、URL、提供商、推理兼容设置和 PasswordSafe 密钥不变。

站点编辑窗口中的模型输入继续允许手工输入；保存时把当前模型加入模型列表。点击获取模型后，将接口返回列表合并到站点模型列表，去重并过滤空值，同时保留当前手工模型。

### 快照和持久化

生成任务仍使用设置快照。快照需要深复制 `apiConfigs` 及每个站点的 `models`，避免生成过程中切换站点或模型改变在途请求。

快速切换直接修改应用级设置对象：

- API 模式：更新 `activeApiConfigId`，并更新目标站点的 `model`。
- CLI 模式：保留现有模型切换逻辑。

IDEA 的 `PersistentStateComponent` 生命周期负责后续持久化，不额外引入配置文件写入。

## 快速切换菜单

API 模式菜单采用两级站点结构：

```text
选择提交信息模型
  https://api.llm.pm                         >
      ✓ glm-5.3-次
        glm-4.7
        deepseek-v4
  amd                                      >
      ✓ DeepSeek-V4-Flash
        DeepSeek-V3
  https://happycoding.xyz                   >
      ✓ minimax-m3
  ─────────────────────────────────────────
  管理模型配置…
```

交互规则：

- 站点显示名称；名称为空时回退到 Base URL。
- 打开 API 快速菜单时先在后台调用每个站点的现有模型列表接口；成功结果与当前模型、已保存列表合并去重，请求失败的站点保留原列表。
- 模型请求全部结束后再展示菜单，避免在 Swing UI 线程中执行网络请求。
- 当前激活站点在一级菜单显示为 `✓ 站点名称 — 当前模型`，未激活站点只显示站点名称；进入子菜单后当前模型继续显示选中状态。
- `model` 不在列表中时临时加入菜单，避免旧配置或手工配置不可选。
- 当前站点的当前模型显示选中状态。
- 点击模型后同时切换活动站点和该站点当前模型。
- 生成任务运行期间菜单禁用，防止改变在途任务。
- 没有站点或模型时显示禁用的空状态项。
- “管理模型配置…”继续打开现有设置页。
- 生成失败自动打开该菜单时，标题使用失败提示文案，但结构和选择行为相同。

## 设置页操作

API 模式的站点操作行调整为：

```text
[新增] [编辑] [删除] [测试] | [导入] [导出]
```

导入和导出按钮与站点表格同一面板，CLI 模式不显示这两个操作。

### 导出

点击“导出”后弹出导出选项对话框：

- 复选框“包含 API Key”，默认不勾选。
- 勾选时显示明文密钥提示，并要求用户确认继续。
- 使用 Windows 兼容的保存文件选择器，默认扩展名为 `.json`。
- 导出全部 API 站点，而不是仅导出当前选中站点。

导出 JSON 使用版本化结构：

```json
{
  "format": "generate-commit-message.api-sites",
  "version": 1,
  "activeConfigId": "site-id",
  "includeApiKeys": false,
  "configs": [
    {
      "id": "site-id",
      "name": "站点名称",
      "provider": "openai",
      "baseUrl": "https://example.com/v1",
      "model": "model-a",
      "models": ["model-a", "model-b"],
      "reasoningCompatible": false
    }
  ]
}
```

当用户勾选 API Key 时，密钥字段仅出现在对应站点对象中；未勾选时不得写入空的或脱敏的密钥字段，避免误以为可恢复。

### 导入

点击“导入”后使用 Windows 兼容的打开文件选择器，解析并完整校验 JSON。校验顺序：

1. 根对象存在且 `format` 与 `version` 匹配。
2. `configs` 为数组，站点 ID、名称、URL、提供商和模型字段类型正确。
3. URL 通过现有站点 URL 校验；模型列表过滤空值并去重。
4. 站点 ID 不为空且在文件内唯一。

任何校验失败都显示错误信息，并保证当前设置、PasswordSafe 和活动站点均不改变。

校验通过后按以下规则合并：

- 文件中的站点 ID 已存在：覆盖站点的非密钥字段。
- 文件中的站点 ID 不存在：新增站点。
- 文件不含 API Key：保留现有站点的本机密钥；新站点不创建密钥。
- 文件含 API Key：使用文件中的密钥更新 PasswordSafe；空密钥不覆盖已有非空密钥。
- 导入后活动站点优先使用文件的 `activeConfigId`，无效时保留当前活动站点，再无效时选择第一个站点。
- 导入操作作为一次性变更应用，不能出现部分站点已写入、后续站点失败的状态。

导入完成后刷新站点表格、活动站点下拉框和当前选择；提示新增、覆盖和保留密钥的数量。

## 错误处理与安全

- API Key 默认不导出。
- 勾选导出 API Key 时必须二次确认，并在文案中明确“文件包含明文密钥”。
- API Key 继续只通过 `PasswordSafe` 保存和读取；普通设置 XML 与导出文件是否包含密钥由用户显式选择。
- 文件读写失败、取消选择、无权限、编码错误和 JSON 解析错误均显示可理解的错误提示。
- 导入失败不得调用设置模型的 `apply`，不得清理或覆盖 PasswordSafe。
- Windows 路径使用 IntelliJ `FileChooserDescriptor` 和平台文件选择器，不手工拼接路径分隔符。

## 测试策略

增加单元测试和现有测试扩展，至少覆盖：

- 旧站点配置从单模型迁移到模型列表。
- 模型列表去空、去重并保留当前模型。
- 快速菜单按站点分组，选择模型后同步站点和当前模型。
- 删除或失效站点后不能选择旧菜单项。
- 导出默认不包含 API Key。
- 勾选导出时包含 API Key，并要求确认的决策逻辑可测试。
- 同 ID 导入覆盖现有站点。
- 无密钥导入保留本机密钥。
- 含密钥导入更新 PasswordSafe。
- 非法 JSON、未知格式、未知版本、重复 ID、无效 URL 和错误字段类型不产生任何配置写入。
- 导入后活动站点选择规则。
- 中英文资源键一致。
- Windows 路径和中文文件名通过平台文件选择器调用，不依赖 Unix 路径分隔符。

```powershell
D:\gradle-7.4.2\bin\gradle.bat test buildPlugin --no-daemon --console=plain
```

## 验收标准

1. 在提交面板模型菜单中能看到每个站点及其多个模型，并能直接切换任意站点模型。
2. 切换后再次生成提交信息使用所选站点和模型。
3. 生成失败弹出的菜单具有相同的站点分组和模型选择能力。
4. 设置页能导出全部站点，默认不包含 API Key，勾选后可明确确认导出。
5. 设置页能导入站点 JSON；同 ID 覆盖，无密钥保留本机密钥，校验失败无部分写入。
6. Windows 下文件选择、中文路径、取消操作和文件读写错误均可正常处理。
7. 现有 CLI 模式、提交生成、模型测试和 PasswordSafe 行为不回归。
8. 完整测试和插件构建通过。
