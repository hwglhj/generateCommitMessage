# API 模型缓存与单站点刷新设计

## 目标

快速切换模型必须立即打开，不再为了展示菜单而请求全部 API 站点。每个站点保存上一次成功获取的模型列表，用户可以在快速菜单或 API 配置页中只刷新一个站点。

本次改动覆盖：

1. API 快速切换默认读取持久化缓存，不自动联网。
2. 每个 API 站点都能单独重新获取模型列表。
3. 获取成功才替换该站点缓存；失败、取消或空结果均保留原缓存。
4. 显示模型数量和上次成功获取时间，帮助用户判断缓存状态。
5. 生成失败后弹出的快速菜单同样直接读取缓存，不增加等待。

CLI 模型列表行为不在本次改动范围内。

## 已确认的交互

### 快速切换菜单

点击工具栏“快速切换模型”后，菜单同步读取 `AiCommitSettings` 中各 API 配置的缓存并立即显示，不启动后台网络任务。

一级菜单继续按站点分组：

```text
✓ happycoding.xyz — minimax-m3  >
api.llm.pm                       >
amd                              >
──────────────────────────────────
管理模型配置…
```

每个站点的子菜单按以下顺序组织：

```text
重新获取此站点模型        ↻
────────────────────────────
○ gpt-5.5
● claude-sonnet-4-5
○ qwen3.5-plus
────────────────────────────
缓存 3 个 · 上次成功：10-15 14:32
```

- 刷新入口使用 IntelliJ 自带刷新图标，与普通模型项形成明确区分。
- 当前活动站点继续在一级菜单显示勾选标识和当前模型。
- 当前模型继续在子菜单中显示选中状态。
- 缓存为空时显示“暂无缓存模型”，但仍保留刷新入口和配置管理入口。
- 正在刷新某站点时，该站点的刷新操作禁用并显示“正在获取模型…”。其他站点仍可刷新或切换。
- 点击刷新后只请求该站点，一级站点菜单和当前站点子菜单都保持打开，不闪烁、不关闭。
- 刷新成功后，当前子菜单原地替换为最新模型列表，并同步更新选中状态、模型数量和成功时间；不需要重新点击“快速切换模型”。
- 刷新失败、取消或结果被丢弃时，原模型列表保持不变，失败状态也在当前子菜单中原地更新。

### API 配置页

API 配置工具栏增加“刷新模型”按钮，作用于表格当前选中的配置：

- 没有选中配置时按钮禁用。
- 刷新期间按钮禁用，状态栏显示正在刷新的站点名称。
- 成功后刷新表格和状态栏，显示缓存模型数量及成功时间。
- 失败后显示错误摘要，原缓存不变。
- 现有“添加、编辑、删除、测试、导入、导出”入口保持原顺序和行为。

编辑 API 配置对话框中的“获取模型列表”继续保留，并与快速菜单、配置页采用相同的缓存更新规则。

## 数据模型

`ApiProviderConfig` 继续使用现有字段：

- `model`：当前选择的模型，也是提交生成实际使用的模型。
- `models`：上一次成功获取的模型缓存。

新增字段：

- `modelsFetchedAt: Long`：缓存最后一次成功更新的 Unix 毫秒时间；`0` 表示从未成功刷新或时间未知。

模型缓存随 `ai-commit.xml` 持久化，使 IDE 重启后仍能立即打开快速菜单。API Key 的存储方式不变，继续只使用 IntelliJ PasswordSafe。

站点 JSON 导入导出继续包含 `model` 和 `models`，不导出 `modelsFetchedAt`。导入到另一台设备后可立即使用导入的模型列表，但界面显示“获取时间未知”，避免把另一台设备的时间误认为本机刷新记录。

## 缓存更新规则

刷新站点时先创建配置快照并解析 PasswordSafe 中的 API Key，然后在后台调用现有 `ApiClient.fetchModels`。

只有同时满足以下条件才写入缓存：

1. 请求正常完成；
2. 返回至少一个非空模型；
3. 当前配置仍然存在；
4. 当前配置的 ID、提供商和 Base URL 与请求快照一致。

成功结果按以下规则生成新缓存：

1. 应用刷新结果时，保留该站点此刻手工填写或正在使用的 `model`，而不是请求开始时快照中的旧模型；
2. 加入接口本次返回的模型；
3. 去除空值和重复值；
4. 替换旧缓存，而不是与旧缓存永久累加；
5. 更新 `modelsFetchedAt`。

因此，下线的旧模型会在下次成功刷新后消失；即使用户在刷新期间切换了模型，也只保留应用结果时正在使用的模型和最新接口结果。

请求异常、取消或返回空列表时不修改 `models` 和 `modelsFetchedAt`。用户仍可使用旧缓存切换模型。

## 代码结构

新增纯逻辑组件 `ApiModelCache`，集中处理：

- 规范化成功返回的模型列表；
- 创建带站点身份信息的缓存更新结果；
- 校验请求快照是否仍匹配当前配置；
- 将成功结果应用到目标配置；
- 生成缓存模型数量和时间状态所需的数据。

网络请求仍由 `ApiClient` 完成。Swing 界面只负责启动后台任务和原地更新菜单，不在 EDT 上访问网络。

快速菜单继续使用 IntelliJ 原生 Action Popup 样式。站点子菜单使用动态 `ActionGroup`，每次重建项目时读取当前缓存；刷新 Action 标记为保持 Popup 打开。由于 IntelliJ 2022.2 的嵌套 Action Popup 默认会在执行普通 Action 后关闭，项目提供一个小型 Popup 适配层，只覆盖站点子菜单的选择处理和列表模型同步：刷新开始时保留两层窗口，后台任务完成后替换当前 `ActionPopupStep` 的项目并同步 `ListPopupModel`，不销毁或重建窗口。

受影响的现有组件：

- `QuickModelAction`：删除打开菜单时的全站点刷新；增加站点级刷新操作和按站点并发保护。
- `QuickModelPopupSupport`：保持嵌套 Action Popup 打开，并将最新站点模型 Action 原地写入当前列表。
- `ApiModePanel`：增加对选中站点的刷新按钮和状态反馈。
- `ApiConfigDialog`：成功获取后按新规则替换缓存并记录成功时间。
- `ApiProviderConfig`：增加成功时间字段，保持深复制和旧配置迁移兼容。
- 中英文资源包：增加刷新、缓存状态、空缓存和失败提示。

## 并发与一致性

- 使用站点 ID 记录正在刷新的配置，不再使用阻止所有站点刷新的全局布尔锁。
- 同一个站点不能同时启动两次刷新。
- 不同站点可以分别启动刷新；一个坏站点不会阻塞其他站点。
- 刷新期间仍允许使用缓存切换模型。
- 如果刷新过程中站点被删除，结果直接丢弃。
- 如果刷新过程中站点提供商或 Base URL 被修改，旧请求结果直接丢弃，避免把模型列表写入错误站点。
- 在编辑站点时修改提供商或 Base URL，会使原端点的模型缓存和成功时间失效；新端点刷新成功后再建立新缓存。
- 提交生成继续使用独立设置快照，刷新或切换不会改变已经发出的请求。

## 错误反馈

快速菜单刷新失败时：

- 保留旧缓存；
- 保持当前两层菜单打开；
- 在对应站点子菜单底部原地显示本次失败的简短状态；
- 详细异常只进入工具提示或错误对话框，不把 API Key、Authorization 头或完整请求内容写入界面。

API 配置页和编辑对话框刷新失败时继续使用现有错误展示方式，但文案明确说明“已保留上次缓存”。

## 兼容性

- 旧配置没有 `modelsFetchedAt` 时按 `0` 处理。
- 旧配置只有 `model`、没有 `models` 时，现有迁移逻辑继续把当前模型加入缓存。
- Windows 上继续使用现有 JDK `HttpClient` 和 IntelliJ 后台任务，不新增命令行或平台相关依赖。
- 现有 API Key PasswordSafe、站点导入导出、活动站点标记、生成失败弹窗和 CLI 模式行为不得回归。

## 测试与验收

自动化测试至少覆盖：

1. 打开 API 快速菜单只读取缓存，不调用模型获取接口。
2. 单站点刷新只请求目标配置。
3. 成功刷新用“应用结果时的当前模型 + 最新返回结果”替换旧缓存并记录时间。
4. 异常、取消和空列表保留旧缓存及原成功时间。
5. 站点被删除或提供商、Base URL 改变时丢弃过期结果。
6. 同一站点不能重复刷新，不同站点互不阻塞。
7. 没有缓存的站点仍显示独立刷新入口。
8. 生成失败弹出的菜单不触发全站点网络请求。
9. 旧配置加载后仍包含当前模型，成功时间默认为未知。
10. API 配置深复制和生成快照包含缓存列表及成功时间。
11. 导入导出不包含成功时间，API Key 行为保持不变。
12. 中英文资源键完整。
13. 刷新 Action 保持嵌套 Popup 打开，完成后用最新缓存替换当前可见 Action 列表。

人工验收：

1. 配置一个响应正常和一个长时间无响应的 API 站点。
2. 点击快速切换按钮，菜单应立即出现，不等待任一站点。
3. 在正常站点子菜单中刷新，只更新该站点模型和成功时间。
4. 刷新异常站点，取消或等待失败后仍能使用旧缓存切换。
5. 在 API 配置页选中不同站点，刷新按钮只作用于当前行。
6. 重启 IDE 后缓存仍在，快速菜单仍能立即打开。
7. 点击“重新获取此站点模型”后，一级菜单和站点子菜单均不关闭；成功后当前列表直接变为最新结果。
