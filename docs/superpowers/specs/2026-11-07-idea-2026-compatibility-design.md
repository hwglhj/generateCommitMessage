# IDEA 2026.1.5 至 2026.3 兼容与更新来源

目标：保留提交生成、失败后选模型自动重试、模型缓存及 CLI 终端入口，支持 IDEA 2026.1.5、2026.2、2026.3，并解决升级后无法识别更新来源的提示。

## 已确认的原因

2026.3 日志显示插件 1.0.1 已加载。提示来自 IDEA 的 `PluginUpdateSourceService`：迁移后的插件没有更新来源记录，且不在 Marketplace 或已配置的自定义仓库中。GitHub 项目页不是更新仓库。

2026-11-07 使用官方 Plugin Verifier 1.411 校验当前 1.0.1 ZIP：IU-261.27258.48、IU-263.7307.200 均为 Compatible，无缺失类或方法；有废弃及计划移除 API 警告。2026.2 尚无本地验证环境。

## 方案

沿用 GitHub 发布方式，构建同时生成 ZIP 和 JetBrains 标准 `updatePlugins.xml`。清单从构建后的 plugin.xml 读取 ID、版本、兼容范围，下载地址指向同版本 Release 的 ZIP。Release 工作流先测试和构建，再一起上传两个文件。

IDEA 的更新仓库地址使用 GitHub 最新正式 Release 的固定资产链接。首次发布并验证该地址后，在 IDE 配置此仓库，并为已有安装选择该更新来源。插件自身不写 IDE 私有更新来源状态，也不伪造 Marketplace 来源。

Marketplace 发布需要额外的账户与审核；继续只分发 ZIP 无法提供可识别的更新渠道，因此采用自定义仓库。

兼容范围保留原最低平台 222，不通过修改版本声明掩盖问题。配置官方校验目标 2026.1.5、2026.2、2026.2.4、2026.3；缺少的 IDE 验证环境按用户要求先取得安装授权。

## 验收

- 构建生成可安装 ZIP 和标准更新清单；清单 ID、版本、范围及文件名与 ZIP 内 plugin.xml 一致。
- 现有 105 项回归、插件结构验证通过；保留失败弹窗选模型后的自动重试。
- 官方二进制检查按版本记录实际结果，未执行的版本明确标记。
- 发布后再检查更新清单及 ZIP 的真实远程可用性，并确认 IDEA 可以选择该来源。

后续用户指出仍未发布新版、提示仍存在，继续要求完成发布。版本提升为 1.0.2；通过 GitHub Release 工作流下载官方发行包，在运行器上补齐四个版本的兼容检查，全部通过后才上线。用户的 IDEA 正在运行时，通过插件设置选择真实更新来源，不在后台改写运行中的配置文件。
